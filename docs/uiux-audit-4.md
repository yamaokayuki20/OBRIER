## 0. 結論

# リリース可否：**不合格**

前回の Blocker（N3-1 焦点の復帰）は**完全に解消**した。それどころか、ゲートが一度も見ていなかった開き口——**削除の確認（入れ子）／1on1準備メモ／権限・チーム変更の確認／監査ログCSV／上司の拡大詳細**——を新しく測っても、**8つの開き口 × 2つの動き設定 = 16通りすべてで、閉じたあとの焦点が開いた場所へ戻る**。N3-2（読み上げ名と付箋の追随）、N3-4（入れ子の `inert`）、N3-5（状態表示の見出し）も解消している。

ユーザーが実物を触って出した15項目（#18〜#24）の作りは、**これまでで最も質が高い**。とくに次の3つは、指摘の字面ではなく指摘が守ろうとしたものを守っている。

- **⋯ の中へお気に入りを畳んだのに、状態は畳まなかった**（日付の右の押せない星＋項目名そのものが状態を語る二本立て）
- **しゃぼん玉の名前を、見た目と読み上げで別々に作らなかった**（小さい玉には名前を描かないが、読み上げ名には必ず名前と通数が入る）
- **原則8は、新しい出口（⋯メニュー・fav-mark・しゃぼん玉）を3つ増やした変更のあとも 53場面で漏れ0**

それでも不合格とするのは、**MUST が2つ満たされていない**からである。どちらも rev.19 が壊したものではなく、**rev.17 の頃から在り、私自身が3回とも「○」と書いてきた**ものである。

> **A4-1（Blocker・FM-2）じぶんのメモの入力欄が、スマホで15px。**
> `@media (max-width: 640px) { input, select, textarea, .search-input, .memo-ta, .select, .adm-select { font-size: 16px } }`（L244〜247）は**正しく書かれている**。しかし `.adm-select`（L515）と `.memo-ta`（L686）が**そのあとで** `font-size: var(--fs-ui)`（スマホ15px）を上書きしている。メディアクエリは詳細度を上げないので、後ろが勝つ。
> 実測（390×844）：`.memo-ta` **15px**／管理者の `.adm-select` **24個すべて15px**。ほかの入力欄（`.select` `.search-input`）は16pxで正しい。
> **iOS Safari は16px未満の入力欄に焦点が当たるとページごと拡大する。** このサービスでいちばん個人的な入力欄——じぶんのメモ——を書こうとするたび、画面が勝手に飛ぶ。コード中のコメントは「素直に16pxにする」と書いてあり、**意図は正しく、効いていない**。

> **A4-2（Blocker・AC-12）320px で横スクロールが出る（管理者／監査ログ）。**
> 実測：`scrollWidth 338 > clientWidth 320`。実際に `window.scrollTo(300,0)` で **18px 横へ動く**。原因は絞り込みの `#auWho`（「操作した人：すべて」）の `select` が**内容なりに302px**まで伸びること。`.select` に `max-width` が無い。
> 340px 以上では出ない。**320px は WCAG 2.1 SC 1.4.10（Reflow・AA）が定める幅**であり、監査基準 AC-12 の MUST そのものである。

**どちらも直しは1〜2行。** A4-1 は `@media` ブロックを `<style>` の末尾へ移す（または `.adm-select` / `.memo-ta` から `font-size` を外す）。A4-2 は `.select { max-width: 100%; min-width: 0 }`。**世界観にも設計原則にも `decision-log` の決定にも触れない。**

そして**この2件は、いまのゲート20項目でも `check.mjs` 15項目でも、原理的に検出できない**（§6）。**6件目の盲点は在った。**

## 2. 今回とくに見てほしかったこと — 1件ずつ

### 2.1 削除がたくさん入っている（#18・#23・#24）

**画面に出る文字としての消し残しは0件。** 14場面の可視テキストを走査し、「年間アルバム」「これまでの節目」「1年前の今日」「実績として書き出す」「STAR」「過去のじぶんと重ねる」「表で見る」「これは感謝ではない」の8語の出現は**すべて0**。押せるのに何も起きないリンクも0。関数・イベント結線（`btnYear` `btnPastMs` `refToday` `cardYMD`）も**すべて0件**で、残骸を残していない。

**消しすぎ**も見当たらない。「表で見る」はボタンだけを外して表そのものは `clip-path` で視覚的にのみ隠してあり、読み上げには残っている（D-66）。推移を累計にしたことで「いちばん右の月は集計中」という注記が要るようになった点も、ちゃんと足されている。

残っているのは次の3つ。

#### A4-3（Major）検出品質モニタの「「感謝ではない」の報告 7件」

報告する導線は #24 で無くなったのに、管理者画面には件数と、その下に**「「感謝ではない」の報告は、判定の学習（負例の追加としきい値の調整）に使います。」**という説明文が残っている。

**この不整合をどう見るか。** 「見落とし」ではない。`decision-log` **D-75 が、残っているものを2か所とも列挙したうえで「報告する手立てが無いまま件数だけを数え続ける形は残骸になる」と書き、(a) F02を機能ごと取り下げる／(b) 導線を別の場所へ移す のどちらかをユーザーに決めてもらう必要がある、と明記している。** 対応表 No.2 で「対応する」と決めた機能を独断で取り下げないという判断は、`CLAUDE.md` の「『対応しない』と決めた機能を勝手に実装しないこと」と対をなす規律で、正しい。

ただし**この状態のまま出荷はできない**。管理者は「7件の報告があった」と読むが、その7件を生む手立ては社内のどこにも無い。数が事実を指していないことは、このサービスがいちばん壊してはいけないもの（TR-1 の精神）に近い。**リリース前にユーザーの判断を1つ得ること**が要る。判断が (a) なら、外すのは4行（`.stat` 1つと `lock-note` の1文）。

> なお TR-1（同一の事実を表す数値が全画面で一致）には抵触しない——この7件はどこにも重複していない。だから MUST 違反には数えず、Major とする。**A-43（誤検出報告の件数推移が無い）は、この判断に吸収される。**

#### A4-4（Major）ドキュメントと実装の食い違い

`CLAUDE.md` は「今回実装する確定機能」として **F02誤検出報告／F13 STAR／年間アルバムPDF／カタチの経年比較**を挙げているが、4つとも実装から外れた。要件定義（F02・F13・F18・F20・F24・画面一覧S01/S02/S05）、基本設計（S01/S02/S05/S09(d)・`DetectionFeedback`・権限表）、詳細設計（1.4.3・`POST /api/cards/{id}/feedback`・`POST /api/me/export/annual`・STAR整形）に、**削除された機能の仕様が丸ごと残っている**。

`CLAUDE.md` は「ドキュメントと現行プロトタイプで仕様が食い違う場合は、**現行プロトタイプを正とし、ドキュメント側を直す**」と定めている。ところが `decision-log` を見ると、#18（STAR・経年比較）は **D-64 に記録がある**のに、**#22/#23（年間アルバム・これまでの節目・1年前の今日の削除）には D-エントリが1つも無い**。コミットメッセージには「ドキュメント側も直す必要がある。別途対応」と書かれたまま、別途対応が来ていない。

**これは UI の欠陥ではないが、リリースの欠陥である。** この状態で実装フェーズへ渡すと、実装者は消えた機能を作る。**難易度：中**（3文書 + CLAUDE.md の改版と、D-76 相当の決定記録）。

#### A4-9（Minor）年間アルバムの死んだ資産

`.book / .book-cover / .book-title / .book-months` のCSS（L715〜720）と、起動時に走る `ANNUAL.months = …` / `ANNUAL.sub = …`（L2821〜2825）が残っている。読む相手はもう居ない。**難易度：低**。

#### A4-10（Minor）見逃した節目は二度と見られない

「これまでの節目」を外したので、帯を見逃す（または✕で閉じる）と、その節目は `localStorage` に既読が入って二度と出ない。**5.5秒で自分から引っ込むものに、取り戻す道が無い。** コミットには「この割り切りでよいか、後で確認する」とあり、`decision-log` には記録が無い。**ユーザー判断が要る**（N-05「触らず5.5秒置いただけで既読になる」と合わせて考えたい）。

## 6. ゲートの6件目の盲点 — **在った**

いま `uiux-gate.mjs` は20項目、`check.mjs` は15項目で、**両方とも合格を返す**。しかしその20＋15項目のどれ一つとして、A4-1 も A4-2 も見ることができない。理由は3つある。

### 盲点⑥ 画面幅が2つしかなく、**横あふれを測る項目が `uiux-gate` に1つも無い**

- `uiux-gate.mjs` が使う幅は **1280 と 390 だけ**。**320px は一度も開かれない**
- 横あふれの項目そのものが `uiux-gate` に**無い**
- `check.mjs` には「横スクロールが無い」があるが、**1280と390で、しかも起動直後のアルバム画面1枚だけ**。ロールもタブも切り替えない

結果：**AC-12（MUST）の違反が、rev.17 → rev.18 → rev.19 と3版にわたり素通りした。** 私自身も1〜3回目で「AC-12 ○」と書いている。**320pxで管理者画面を一度も開いていなかった**からである。

### 盲点⑦ **「書いたのに効いていないCSS」を、計算値で照合する項目が無い**

前回、閉じ括弧の落下で後半のスタイルが丸ごと無効だったのに20項目が全部○のまま通った。その反省で「括弧の釣り合い」を見る項目が入った。**しかし括弧は同じ事故の一形態にすぎない。**

A4-1 は括弧が合っていても起きる。`@media (max-width:640px){ … .memo-ta { font-size:16px } }` は**存在し、括弧も合っている**。ただ、**後ろに来る `.memo-ta { font-size: var(--fs-ui) }` に負けている**だけである。ソースを読むかぎり正しく見え、コメントまで丁寧に書かれている。**効いているかどうかは、計算値を測らないと分からない。**

同じ形の事故は、この画面で**すでに2回起きている**——`.bub` の名前衝突（D-73。後から書いた節が拡大詳細の吹き出しに当たっていた）と、閉じ括弧の落下。**3回目である。**

### 盲点⑧（機構）**巡回するはずの場面が開けなくても、黙って通り過ぎる**

`uiux-gate.mjs` の焦点復帰の検査が開こうとするダイアログは、いまも

```
['CSVで書き出す', 'CSV'], ['年間アルバム', '年間アルバム'], ['これまでの節目', '節目一覧']
```

の3つである。**後ろ2つは #23 で消えた。** ボタンが見つからないと `catch { continue }` で**黙って飛ばす**ので、「どのダイアログも、閉じたら焦点が開いた場所へ戻る」は**実質 CSV と拡大詳細の2つしか測っていない**。

いま実在する **削除の確認（入れ子）・1on1準備メモ・権限／チーム変更の確認・監査ログCSV・上司の拡大詳細**は、焦点の復帰も `inert` も**一度も測られていない**（今回は私が測って、5つとも○だった。だが**通ったのは偶然ではなく実力**であって、それを機械が知らないままなのが問題である）。

これは「①ダイアログ内とメンバー詳細を巡回していなかった」「②巡回の入口が隠れた表の行に当たっていた」と**同じ事故の3度目**である。画面が変われば巡回表は必ず腐る。**腐ったことを機械が言わない限り、同じことが起き続ける。**

### 足すべき項目（5つ）

| # | 項目 | 実装 |
|---|---|---|
| 1 | **320px を含む全幅 × 全画面・全タブで `scrollWidth <= clientWidth`** | 幅の配列に320を足し、`visitAll` の各場面で測る。**A4-2 をここで捕まえる** |
| 2 | **スマホ幅で `input/select/textarea` の計算 `font-size >= 16`** | 全場面。**A4-1 をここで捕まえる** |
| 3 | **巡回するはずの場面が本当に開いたかを数え、開けなかったら不合格にする** | `visitAll` に「開くつもりだった数」と「実際に開けた数」を持たせ、食い違ったら `check('巡回した場面が想定どおり', false, どれが開けなかったか)`。**黙って `continue` しない** |
| 4 | **`@media` の意図を計算値で照合する表** | 「スマホで `.menu-item` は44px以上」「`.memo-ta` は16px以上」「`.sheet-close-wide` は52px以上」…を一覧にして、スマホ幅の計算値と突き合わせる。**「書いたのに効いていない」を、括弧以外の形でも捕まえる** |
| 5 | **節目の帯（RS-3）の重なりと、押せるものを塞いでいないか** | `.ms-host .ms` の矩形と `.say / .who-line / h1` の交差、および `elementFromPoint` のヒットテスト。**A4-5 をここで捕まえる** |

**そして、いちばん大事なこと。** ゲートに項目を足すたびに、私たちは「測っているところ」を広げてきた。だが4回とも、**不合格の理由は必ず「測っていないところ」から出ている**。20項目それぞれが「その観点を測れているか」を疑うことは、これからも要る——**とくに、その項目が通り続けているときほど。**
