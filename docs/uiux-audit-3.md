## 0. 結論

# リリース可否：**不合格**

前回の指摘（部分的4／未解消5／新規10）のうち、**MUST に関わるものは4つが完全に解消した**。A-03（コントラスト）は 47場面×4幅で**不足0件**、A-11（当たり判定）は 320/390/768/1280/1920 の5幅で**24px未満0件**、A-30（見出し）は全画面で **h1がちょうど1つ・h1 24px＝本文の1.5倍・h2 20px＝1.25倍**、N-01（節目の帯）は基準の2幅（1280×900・390×844）で**本文への重なり0**。原則8（じぶんのメモ）は79場面の総当たりで**漏れ0件**——A-39でカードに読み上げ名が付いたあとも、上司・管理者にはメモの存在すら伝わっていない。

それでも不合格とするのは、**A-02（背景の `inert`）の修正が、同じ AC-5 の別の条項を壊した**からである。

> **ダイアログを閉じたあと、焦点が起動要素へ戻らない。**
> CSVで書き出す／年間アルバム／これまでの節目／STAR／1on1準備メモ／権限変更の確認——**`openDialog` を使う6種すべて**で、閉じたあとの `document.activeElement` が **`body`** になる。
> さらに **`prefers-reduced-motion: reduce` の環境では、拡大詳細も**（Escape・✕・背景クリックのいずれで閉じても）元のカードへ戻らない。
>
> **これは回帰である。** #15の前（`3969df3`）を同じ手順で測ると、4通りすべてで正しく戻っていた。

原因は1点。`popModalFocus()` が `syncScrollLock()`（→ `syncBackgroundInert()`）を呼ぶ時点で幕（`.overlay`）はまだDOMに残っており、`main` は `inert` のままである。`inert` な器の中の要素は `focus()` を受け取れないので、戻し先への `el.focus()` が黙って無効になる。拡大詳細が通常時だけ助かっているのは、裏返りの380msのあいだカードが `visibility:hidden` で、`tryFocus` が `requestAnimationFrame` で待っている**あいだに幕が消えて `inert` が外れる**からで、偶然に近い。動きを止めた環境では待ちが発生せず、その偶然が働かない。

**キーボードだけで使う人にとっての実害**：CSVダイアログを閉じるたびに文書の先頭へ放り出され、ヘッダー（スキップリンク・タブ3つ・ロール3つ・自己診断）とツールバーを毎回たどり直すことになる。`reduced-motion` を選んでいる人は、カードを1枚読むたびに同じことが起きる。

**残っているのはこの1件だけで、難易度は「低」**（`popModalFocus` の中で「戻し先が `inert` の中にある間は待つ」を1行足すか、`close()` の中で `ov.remove()` を `popModalFocus()` より先に出す）。世界観にも設計原則にも触れない。**これを直せば合格である。**

### N3-1（Blocker）閉じたあと、焦点が起動要素へ戻らない

**実測（#15の前後を同じ手順で比較）**

| 場面 | `reduced-motion` | #15の前（`3969df3`） | 現行（`03c6b15`） |
|---|---|---|---|
| 拡大詳細を Escape で閉じる | なし | `card` ○ | `card` ○ |
| CSVダイアログを Escape で閉じる | なし | `btn#btnCsv` ○ | **`body` ×** |
| 拡大詳細を Escape で閉じる | あり | `card` ○ | **`body` ×** |
| CSVダイアログを Escape で閉じる | あり | `btn#btnCsv` ○ | **`body` ×** |

**現行で焦点が失われる場面（実測・すべて `body` に落ちる）**

| ダイアログ | 起動要素 |
|---|---|
| CSVで書き出す | `#btnCsv` |
| 年間アルバム | `#btnYear` |
| これまでの節目 | `#btnPastMs` |
| 実績として書き出す（STAR） | `.btn` |
| 1on1の準備メモ | `.report-item` |
| チーム変更の確認 | `.adm-select` |
| 拡大詳細（Escape／✕／背景クリック） | `.card` ※`reduced-motion` のときだけ |

**原因**

```
close = () => { …; popModalFocus(focusEntry); ov.remove(); syncScrollLock(); };
                 ↑ この時点で ov はまだDOMにあり、main は inert のまま
```

`popModalFocus()` は先頭で `syncScrollLock()`（→ `syncBackgroundInert()`）を呼ぶが、幕がまだ残っているので `inert` は外れない。そのあとの `el.focus()` は `inert` な器の中では無効になり、例外も出ないまま焦点が `body` へ落ちる。

拡大詳細が通常時だけ助かっているのは、`tryFocus` が「カードが `visibility:hidden` の間は `requestAnimationFrame` で待つ」作りで、**待っているあいだに裏返りが終わって幕が消え、`inert` が外れる**ため。動きを止めた環境では待ちが発生せず、1回目の `focus()` がそのまま無効になって終わる。**偶然で成り立っていたものが、条件が変わって表に出た**という形である。

**直し方（どちらか一方でよい）**

- `popModalFocus` の待ちの条件に「戻し先が `inert` の中にある間」を足す
  `if (n < 45 && (el.offsetParent === null || getComputedStyle(el).visibility === "hidden" || el.closest("[inert]"))) return requestAnimationFrame(...)`
- または `openDialog` の `close()` で `ov.remove(); syncScrollLock();` を `popModalFocus(focusEntry);` より**先**に出す（拡大詳細側は裏返りが380ms残るので、上の待ちの条件が要る）

**難易度：低（1〜2行）。** ただし直したあと、**6ダイアログ × 2つの動き設定**で測り直すこと。

### N3-2（Major）読み上げ名と付箋が、状態の変化に追随しない

**実測**（拡大詳細で★を付け、じぶんのメモを保存して閉じた直後）

## 10. 総括

1回目に「見せたいものは美しく作れているが、使えるかの検証がまだ一度も行われていない」と書いた。2回目に「ゲートが見ているところは直り、見ていないところは残った」と書いた。**3回目に残ったのは、見ているところを直した結果、見ていないところが壊れた1件だけである。**

#15 の修正そのものは、これまでで最も質が高い。`--navy-soft` を1トークンで解いた判断、当たり判定を「見た目を変えず余白だけで広げる」やり方、`background-clip: content-box` で32pxの円を保ったまま44px押せるようにした細工、スマホの h1 を20pxに留めた理由を実測（21pxで折り返し、カードが30px下がる）で説明していること、節目の帯を「押し下げる」でも「隠す」でもなく「そこに何も無い場所へ置く」で解いたこと——いずれも、指摘の字面ではなく指摘が守ろうとしたものを守っている。そして**原則8は、カードに読み上げ名という新しい出口を作った同じ変更の中で、一度も緩まなかった**。79場面の総当たりで漏れ0件である。

不合格の理由は、修正の質でも範囲でもなく、**確かめ方**にある。`inert` は AC-5 の後半を満たすために入れたが、AC-5 の前半（元の起動要素へ戻す）を測る機械は拡大詳細1つしか見ておらず、しかもその1つが偶然だけで通っていた。**同じ基準の中でさえ、測っている条項と測っていない条項がある。**

だからこそ、直す順番は「1 → 2」ではなく「**2 → 1**」を勧める。ゲートに焦点の復帰と `inert` と原則8を足せば、この1件はゲート自身が指し示す。そして次に誰かが `inert` に触ったとき、同じことは起きなくなる。

**残りは1件、難易度は低、世界観にも設計原則にも `decision-log` の決定にも触れない。合格までの距離は、前回よりさらに近い。**
