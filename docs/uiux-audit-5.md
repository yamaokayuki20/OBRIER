## 2. 総括

**rev.20 は、ユーザーが出した2つの大きな指示——「上司はしっかり順位も見るべき」「上司ビューを2階層に」——を、設計としてはよく受け止めている。**

いちばん質が高いのは、**原則6の適用範囲を絞ったときに、絞った側と絞らなかった側の両方をきちんと作り分けている**ことである。上司ダッシュボードは「つながりの数（相手の少ない順）」で人を並べ、「やり取りのあった相手の人数」で並べ替えられ、関係の図では玉の大きさがそのまま量を語る——順位を出すことを一切ためらっていない。いっぽうで、本人の3画面（アルバム／カタチ／おくった）を語彙で総なめしても、**「最も」「トップ」「平均」「チーム内で」「ほかの人」「上位」といった語は1つも出てこない**。唯一出る「最多」は「『対応の速さ』への感謝が最多です」——自分のタグどうしの話であって、人の順位ではない。**順位は上司の画面にだけ在り、本人の画面には1文字も漏れていない。** ここは厳しく見たが、漏れは無かった。

**原則8（じぶんのメモは本人のみ）も、出口が増えたあとで守られている。** ページ内の「`msg` を持つ配列」を総なめして 1,119件のメモを検査用文字列に差し替え、対照（本人の拡大詳細）で確実に漏れることを確かめたうえで、上司サマリ・メンバー詳細6人・1on1準備メモ8件・管理者4タブを走査した。**可視テキスト・全属性・`value` のいずれにも0件。** 新しく足った経路——関係のネットワーク図、つながりの一覧、関係の変化のインサイト文、メンバー表の「つながり」列——は、いずれも `shape.monthly.sent × NET_SHARE` と `partners.size` だけから作られており、**メモを集計値として使っている箇所は1つも無い**（`netFlow` / `netInsights` / `renderNetList` / `renderTeamSigns` をコードでも実行時でも確認）。

**原則7（上司ビューにカードを置かない）も守られている。** 上司サマリ・メンバー詳細とも、**見えているカードは0枚**（DOM上には本人ビューのぶんが残っているが `hidden` の中で、上司には1枚も描かれない）。1on1に要る「引用＋事実＋伝え方例」は「1on1で使えるエピソード」が文章として持っている。

そのうえで**不合格とする。理由は6つで、性格が2つに分かれる。**

**ひとつは「誰も一度も見ていない状態」で壊れているもの。** ポインタを重ねた状態のコントラスト（A5-2）、「もっと見る」で開いた先（A5-2）、並べ替えを実際に押した状態（A5-3）、期間を切り替えた状態（A5-4）、320pxのメンバー詳細（A5-1）。**5回の監査で一度も入ったことのない状態ばかりである。** とくに A5-2 は重い——**「アルバムで見る」は、カーソルを重ねた瞬間に白文字＋タグ色の地になり、7色すべてで 4.5:1 を割る。** いちばん薄いアイデア（黄 `#F5C63C`）で **1.61:1**、気配り（桃 `#F2A0BC`）で **1.99:1**。押そうとして近づいた瞬間に、押そうとしているものの字が消える。しかも 8枚中 8枚が該当し、**畳んだ状態の上位3枚でも起きる**（`#F08A24` で 2.51:1）。

**もうひとつは「作りかけの規律が、新しい面へ伸びていない」もの。** ダイアログの焦点はこの画面の誇るところで、`pushModalFocus` / `popModalFocus` が8つの開き口すべてで正しく往復する。ところが**画面まるごとの入れ替え**（一覧→メンバー詳細、詳細→一覧、カタチ→アルバム）には、その規律がまったく届いていない。焦点は毎回 `<body>` へ落ち、次の Tab は「本文へスキップ」から始まる（A5-5）。`#mainContent` には `tabindex="-1"` が**すでに用意されている**のに、一度も使われていない。同じことが `.tabs` と `.sub-tabs` にも言える——`data-scroll-region` という仕掛けを4か所に入れて「横に送れること」を名前とキーボードで届けているのに、**いちばん重要な主ナビゲーションと管理者のサブタブだけが、その仕掛けの外にあり、しかも `scrollbar-width: none` でスクロールバーまで消してある**（A5-6）。390px——いま日本でいちばん多いスマートフォンの幅——で、**管理者の4つ目のタブ「検出品質」は、右端が 475px、つまり画面の 85px 外にあって、そこに何かがあるという合図が一切無い。**

**4回目に残した宿題は、半分が片づき、半分が5回目に持ち越された。** A4-1（じぶんのメモ・管理者selectのスマホ15px）は**解消**——390pxで測って16px未満は0個。A4-2（320pxの監査ログ）も**解消**——320pxの管理者4タブすべてで横スクロール0。この2件は正しく直っている。いっぽう **A-35（`document.title`）は5回連続、A-36（`font-size:200%`）とA-37（テキスト間隔）は5回連続、A4-3（存在しない報告の件数7件）・A4-5・A4-6・A4-7・A4-8・A4-9・A4-10 は2回連続で、`decision-log` に「対応しない」とも書かれないまま残っている。**

最後に、**A5-7 は A4-3 とまったく同じ形の見落としである。** 監査ログには「アルバム閲覧」6件・「おくった閲覧」3件・「カード詳細閲覧」3件が並び、絞り込みの選択肢にもその3つがあり、パネルの説明は「上司・管理者による**アルバム閲覧**、レポート閲覧、書き出し、設定変更の記録です」と書いてある。**しかし上司ビューからカードは外れた（原則7・D-83）。** これらを生む手立ては、社内のどこにも無い。A4-3 で「削除のチェックリストに『この機能を指していた数字・文書・道は、ほかにどこにあるか』の一行を足す」と書いたが、**同じ削除の別の出口が、まだ1つ残っていた。** 監査ログは導入企業への説明材料そのものなので、ここに事実でない操作名が並ぶのは、検出品質モニタの7件より重い。

### A5-3（Critical・MUST・SC 4.1.2 / AC-14）並べ替えの矢印と読み上げ名が、列をまたいで入れ違う

| | |
|---|---|
| 画面 | 上司 ／ チームのダッシュボード「メンバーごとに見る」の表 |
| 幅 | 全幅 |
| 立場 | 上司 |

**原因はこの1行**（L5835）：

```js
const span = $(k === "recv" ? "sortRecv" : "sortSent");
```

`for (const k of ["recv", "sent", "link"])` の3周目（`k === "link"`）でも `#sortSent`——**「おくった」列の印**——を掴んでしまう。`#sortLink` は**一度も更新されない**。

**実測（4状態を実際に押して確認）**：

| 操作 | `#sortRecv` | `#sortSent` | `#sortLink` | 「おくった」ボタンの読み上げ名 | 「つながり」ボタンの読み上げ名 |
|---|---|---|---|---|---|
| 初期 | ⇅ | ⇅ | ⇅ | 「**つながり**：並べ替えていません。押すと多い順に並べ替えます」 | **（aria-label なし）** |
| つながりを1回押す | ⇅ | **▼** | ⇅ | 「**つながり**：多い順に並べています…」 | （なし） |
| つながりを2回押す | ⇅ | **▲** | ⇅ | 「**つながり**：少ない順に並べています…」 | （なし） |
| おくったを押す | ⇅ | **⇅** | ⇅ | 「**つながり**：並べ替えていません…」 | （なし） |

**4つの不具合が同時に起きている**：

1. **つながりで並べると、▼が「おくった」列に付く。** 目で見ている上司は、押した列と印が付いた列が違う。
2. **おくったで並べても、矢印はどこにも出ない**（`aria-sort="descending"` は `th` に正しく付くが、見える印は ⇅ のまま）。並んでいるのに並んで見えない。
3. **「おくった」ボタンの読み上げ名が、いつも「つながり…」**。スクリーンリーダーの利用者は、おくった順に並べようとして「つながり」と読み上げられる。
4. **「つながり」ボタンには `aria-label` が無い**。⇅ は `aria-hidden` なので、読み上げは「つながり」だけ——いまどう並んでいるかも、押すとどうなるかも伝わらない。

## 5. 判定器の盲点 — **6つ在った**

`uiux-gate.mjs`（29項目）と `check.mjs`（15項目）を、**私が固定した rev.20 スナップショットに対して実際に走らせた**。

```
判定: 合格 — 29項目
判定: 合格 — 15項目
```

その44項目のうち、**A5-1〜A5-6 を検出できるものは1つも無い**。理由は6つに分かれる。

### 盲点⑨ 幅の検査だけが `visitAll` を使っていない — **同じ事故の4度目**

4回目の指摘（盲点⑧）を受けて、`visitAll` は「開けなかった場面を数えて不合格にする」ようになった。**ところが横あふれの検査（L285〜316）は `visitAll` を呼んでいない。** 自前の巡回表を持っていて、まわるのは

```
本人3画面（album / shape / sent） ＋ 上司トップ ＋ 管理者トップ ＋ .sub-tab 各1回
```

だけである。**メンバー詳細を一度も開かない。ダイアログも開かない。期間も変えない。並べ替えもしない。**
だから **A5-1（320pxのメンバー詳細で 336>320）が素通りした。** 4回目で「腐った巡回表」を直したのに、**同じファイルの別のループに、直っていない巡回表がもう1つ在った。**

### 盲点⑩ コントラストを、静止した状態でしか測っていない

`scan()` は `visitAll` の各場面で1回走るだけで、**ポインタを重ねた状態・焦点を当てた状態のコントラストを一度も測らない**。
`.top-card.jump:hover .top-go { background: var(--cc); color: #fff }` は**ホバーしたときにしか存在しない色**なので、静止して何度測っても見つからない。**A5-2 の最も重い部分（8枚中8枚、最悪1.55:1）は、原理的に見えない。**

### 盲点⑪ 「押して初めて出る中身」に入っていない

`visitAll` はタブ・立場・行を押すが、**パネルの中の「もっと見る（TOP8まで）」を押さない**。だから4〜8枚目のカードは一度も描かれない。
**A5-2 の静止時のぶん（`.top-rank` 4:1、`.top-go` 3.73:1）も、ここで落ちている。**
同じ理由で、`.chart-tab`（1週間/1か月/3年/5年）・`#teamPeriod`（6か月/1年）・お気に入り絞り込み・タグ絞り込みも一度も押されていない。

### 盲点⑫ 状態を作らないので、状態のバグが見えない

**並べ替えを一度も押さない。** 押さないので、`#sortSent` に `#sortLink` の印が入ることも、`aria-label` が「つながり」に化けることも起きない。**A5-3 は、押さない限り絶対に現れない。**
さらに根の深い問題として、ゲートには **「`aria-label` の中身が、その部品の名前と一致しているか」を見る項目が1つも無い。** あるのは「焦点が当たったことが見た目で分かる」だけで、**名前が正しいかは誰も見ていない。**

### 盲点⑬ 横あふれを、文書のいちばん外側でしか測っていない

```js
if (r.doc > r.win + 1) bad.push(...)   // document.documentElement.scrollWidth
```

`.tabs` と `.sub-tabs` は `overflow-x: auto` なので、**中身がいくら切れても文書は溢れない**。
だから **A5-6（390pxで「検出品質」が画面の85px外）は 0 と判定される。**
`check.mjs` の「横スクロールが無い」も同じ測り方で、しかも**起動直後のアルバム1枚だけ**である。

### 盲点⑭ TR-1（数値の一致）を機械で見る項目が、そもそも1つも無い

29項目＋15項目に、**数値の整合を見るものが1つも無い**。期間を変えて数が追随するか、注記が宣言した期間と中身が合っているか、合計とタイルが噛み合うか——どれも見ていない。
だから **A5-4（3か月でも1年でも1,460通で固定）は、どのループにも掛からない。**
TR-1 は監査基準の MUST であり、**1回目の監査で「× 不合格（264/265/12枚/12件/2通/6通が混在）」と書かれた項目**でもある。そこがいま、機械の側では完全な空白になっている。

### 足すべき項目（6つ）

| # | 項目 | 実装 | 捕まえるもの |
|---|---|---|---|
| 1 | **幅の検査を `visitAll` に統一する**（自前の巡回表を捨てる） | 320〜1920 の各幅で `visitAll` を回し、各場面で `scrollWidth<=clientWidth` | **A5-1** |

## 8. 最後に — 「順位を出してよい」を受け取ったあとの作り

ユーザーの指示は「非ランキングの話は本人に見せるUIUXの話で、上司は別です。上司はしっかり順位も見るべき」だった。

**この受け取り方は、正しかった。** 本人の画面からは順位が1文字も漏れず、上司の画面では順位をためらっていない。「つながりの数（相手の少ない順）」を**あえて少ない順に並べ**、その真下に「少ないことがそのまま問題だとは限りませんが、支援が要るかどうかは1on1で確かめてください」と書く——**順位を出すことと煽ることを分ける**という原則6の但し書きが、そのまま画面になっている。関係の変化に必ず「＋のサイン」を1件混ぜ、「連携が止まっていた期間・長期の休み・チーム編成の変更があると、関係が減ったのと同じように見えます」と偽陽性の注記を置くのも同じ規律である。**これは指摘の字面ではなく、指摘が守ろうとしたものを守る作りだ。**

だからこそ、**順位を出すために足した並べ替えが、押した列と違う列を指している**（A5-3）ことと、**その隣で「直近3か月」と宣言した画面が直近3か月でない数字を並べている**（A5-4）ことが惜しい。上司が順位を見るのは、**その数を信じて人と話すため**である。数と印が指すものがずれていたら、順位を出した意味そのものが無くなる。

**6件。うち5件は10行前後。合格までの距離は、4回目より近い。**
