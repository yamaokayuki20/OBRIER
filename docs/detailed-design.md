## 1. 画面詳細設計

### 1.1 S01 アルバム

| 要素 | 仕様 |
|---|---|
| 累計カウンター | 受信カード総数を表示。新着反映時に+1しポップアニメーション（0.3秒） |
| 月ディバイダー | 「2026年 7月」形式。カードの綴じ月ごとに挿入 |
| 感謝カード | 送り主（アバター・氏名）／チャンネル名／出所バッジ（Slack/Teams）／本文（明朝体）／場面タグ／受信日時。装飾としてテープ表現と微小な回転（-1.2〜1.2度） |
| 新着演出 | 新規カードは最上部にスライドイン（0.7秒）。NEWバッジを24時間表示 |
| タグ絞り込み | 場面タグのセレクトで絞り込み。絞り込み中は解除チップを表示 |
| CSV書き出し | 表示中の絞り込み条件に従い全項目をCSV出力 |
| お気に入り | カード右上の星ボタンで登録／解除。星シール表示。お気に入りのみ表示の絞り込みに対応 |
| じぶんのメモの目印 | メモがあるカードには付箋の目印を表示 |

### 1.2 S02 あなたのカタチ

| 要素 | 仕様 |
|---|---|
| 場面タグ内訳 | 自動生成された可変タグを件数バーで表示（最大値を100%とする相対表示） |
| 推移チャート | 期間タブ（1週間・1か月・1年・3年・5年）で切替。折れ線2系列（受信・送信）。1週間・1か月は日次、1年以上は月次。3年以上はコンテンツ幅を広げ横スクロール（初期位置は最新側）。通常時は数値ラベルなし。ホバーで縦のクロスヘアと吹き出し（期間ラベル・受信数・送信数）を表示 |
| よく感謝される場面 | 上位3件を表示し「もっと見る」で最大10件まで展開。各カード押下でアルバム画面へ遷移し該当タグで絞り込み |
| 広がりマップ | 部署ごとに送り主チップ（アバター・氏名・累計数）をグループ表示 |
| STAR書き出し | 経緯データを状況（S/T）→行動（A）→結果・感謝（R）に整形しドキュメント出力 |

### 1.3 じぶんのメモ・お気に入り・削除

| 要素 | 仕様 |
|---|---|
| じぶんのメモ | 経緯モーダル内、オブリエのメモの下に付箋風の入力欄。鍵アイコンへのホバー／フォーカスで「このメモはあなただけに表示されます。上司には見えません」とポップアップ表示 |
| メモの権限 | 本人のみ閲覧・編集可。上司・管理者向けAPIレスポンスには含めない |
| お気に入り | カード右上の星ボタンで登録／解除。一覧絞り込み条件に使用 |
| 削除 | 「アルバムから削除」→確認ダイアログ（削除すると元に戻せない旨を明記）→削除。復元機能は提供しない |

### 1.4 S05 経緯モーダル

| 要素 | 仕様 |
|---|---|
| やり取り再現 | 経緯の発言列を時系列表示。感謝発言は強調枠＋「この言葉をアルバムに綴じました」フラグ。添付はファイルチップで表現 |
| オブリエのメモ | AI要約（経緯・回数などの文脈を1〜2文） |
| 誤検出報告 | 「これは感謝ではない」リンク。押下でカードを非表示にし、DetectionFeedbackを登録。トーストで受領を通知 |
| 閉じる操作 | ✕ボタン（34px以上）・背景クリック・Escキー |

### 1.5 S06〜S08 上司ビュー

| 要素 | 仕様 |
|---|---|
| S06 メンバー一覧 | テーブル形式。列＝メンバー（名前・役割・要確認チップ）／もらった数／おくった数／直近6か月スパークライン（2系列）。期間セレクト（1か月＝既定・3か月・1年）で数値を再集計。数値列はクリックで昇降順ソート。名前検索・要確認のみ絞り込みに対応 |
| S07 メンバー詳細 | 上司限定パネル（本人には非表示と明記。1on1準備メモの履歴・アラート）＋本人ビューと同一コンポーネントのアルバム／カタチ／おくった3タブ。カタチは本人画面と完全に同一（タグ内訳・場面言語化・推移チャート・広がりマップ）。じぶんのメモは表示しない |
| S08 1on1準備メモ | 5部構成＝①今月のようす（受信・送信・新しい送り主・増えている場面＋解釈文）②そのまま伝えられる称賛（引用＋事実＋伝え方の例）③気にかけたいサイン（アラートまたは所見）④聞いてみたい問い（2〜3件）⑤前回からの持ち越し（上司メモ欄）。過去月も選択して閲覧可能。PDF書き出し対応 |

## 2. API設計

| メソッド/パス | 概要 | 主な入出力 |
|---|---|---|
| GET /api/me/cards | 自分の感謝カード一覧 | in: tag, favorite, page ／ out: cards[], total |
| GET /api/cards/{id} | カード詳細（経緯・メモ含む） | out: card, story[], summary |
| POST /api/cards/{id}/feedback | 誤検出報告 | in: type=not_thanks ／ out: 204 |
| GET /api/me/shape | カタチ（タグ内訳・場面言語化・推移） | in: period(1w/1m/1y/3y/5y) ／ out: tags[], tops[]（最大10）, series{recv[], sent[]} |
| GET /api/me/network | 広がりマップ | out: groups[{dept, senders[]}] |
| GET /api/me/sent | 送った感謝一覧 | out: cards[] |
| POST /api/me/export | CSV／STAR書き出し | in: format ／ out: ファイルURL |
| PUT /api/cards/{id}/user-meta | お気に入り・じぶんのメモの更新（本人のみ） | in: favorite?, memo? ／ out: 204 |
| DELETE /api/cards/{id} | カード削除（本人のみ・復元不可） | out: 204 |
| GET /api/team/members | メンバー一覧（上司） | in: period(1m/3m/12m), sort, q ／ out: members[{recv, sent, spark[], alert}] |
| GET /api/team/members/{id}/cards | メンバーのアルバム（上司） | out: cards[] |
| GET /api/team/members/{id}/reports | 1on1準備メモの一覧・取得（上司） | in: month? ／ out: months[] または report |
| POST /webhook/slack/events | Slackイベント受信 | Slack Events API準拠 |

全APIは認証必須。上司系APIは対象ユーザーが自チーム所属かを検証し、閲覧を監査ログに記録する。

## 3. データベース詳細設計

### 3.1 主要テーブル

| テーブル | 主なカラム |
|---|---|
| users | id, name, email, avatar_color, team_id, role(member/manager/admin), created_at |
| teams | id, name, company_id, manager_user_id |
| thanks_cards | id, recipient_id, sender_id, source(slack/teams), channel_name, body, category_id, confidence, sent_at, is_hidden, created_at |
| card_stories | id, card_id, seq, speaker_name, spoke_at, body, attachment_name, is_thanks_line |
| card_summaries | card_id, body, generated_at |
| categories | id, name（スピード対応/資料品質/調整力/気配り/アイデア）, color |
| detection_feedback | id, card_id, user_id, type(not_thanks/deleted), created_at |
| card_user_meta | card_id, user_id, favorite(bool), memo_text, updated_at ※本人のみ参照可。上司向けAPIには含めない |
| monthly_reports | id, user_id, month, recv_count, recv_diff, sent_count, sent_diff, breakdown(json), episodes(json), alert_text, note_text, generated_at |

## 4. 検出ロジック詳細

### 4.1 判定パイプライン

| 段階 | 処理 | 備考 |
|---|---|---|
| ① 受信 | 連携層からメッセージ（本文・送信者・宛先・スレッド情報）を受け取る | bot発言・システム通知はここで破棄 |
| ② 候補抽出 | 感謝語彙辞書（ありがとう/助かる/さすが/おかげ/感謝 等）または感謝系絵文字リアクションに一致するものを候補化 | 辞書は運用で更新 |
| ③ LLM判定 | 候補発言＋同スレッド直前最大10件を入力し、JSONで出力：is_thanks／recipient／category（5分類）／is_sarcasm／confidence（0〜1） | 皮肉・社交辞令はここで除外 |
| ④ カード化 | confidence≧0.80のみthanks_cardsに保存。0.80未満は保存せず統計のみ記録 | 閾値は運用パラメータ |
| ⑤ 経緯・要約 | 直前のやり取りからstoryを構成し、オブリエのメモを生成 | 生成失敗時はメモなしで綴じる |

### 4.2 学習フィードバック

- 誤検出報告されたカードは非表示化し、報告事例を判定プロンプトの負例として追加する
- 同一送り主・同一表現での再発を抑えるユーザー別除外ルールを設ける
- 週次で誤検出率をモニタリングし、閾値・辞書を調整する

### 4.3 絵文字リアクションの扱い

感謝系絵文字（🙏 ✨ 👏 ❤ 等）のリアクションは、対象メッセージの投稿者宛ての「小さなありがとう」として件数のみ計上する。カードは生成せず、カタチ・推移の集計にのみ反映する。

## 5. バッチ処理設計

| ジョブ | 起動 | 処理概要 |
|---|---|---|
| 過去ログ取込 | 初回連携時 | 過去1年分を新しい月から順に取得し判定パイプラインへ投入。進捗を管理画面に表示 |
| 1on1準備メモ生成 | 毎月1日 6:00 | 前月分の集計・称賛候補の選定・アラート判定・問い候補の生成を全ユーザー分実行 |
| タグ統合メンテ | 週次 | 類似タグの統合・表記ゆれ正規化の候補を管理者に提示 |
| 週次ダイジェスト | 毎週月曜 8:00 | 先週の受信をまとめ言葉調の文面でメール送信（0件の週は送らない） |

### 5.1 アラート判定ロジック

月次レポート生成時に以下を判定し、該当時のみアラート文を出力する。本人へは通知しない。
- 受信数が前月比50％以上減少し、かつ2か月連続で減少している
- 送信数が前月比50％以上減少し、かつ2か月連続で減少している
- 文面は断定を避け、「〜のサインかもしれません。1on1で聞いてみてください」の形式とする

## 6. 通知文言仕様

| 種別 | 文言テンプレート |
|---|---|
| 週次メール（1件以上） | 件名：今週の、あなた宛てのことば ／ 本文：今週は、あたたかい言葉が{n}通とどいています。{送り主}さんからの一言も、アルバムに綴じてあります。 |
| 新着（アプリ内） | {送り主}さんから、あたたかい言葉がとどいています |
| アラート（上司向けアプリ内） | {name}さんの最新の準備メモに、気にかけたいサインがあります |

## 7. エラー・例外設計

- 連携失敗（トークン失効）：管理者に再認可を促すメールを送り、取込停止期間を記録する
- LLM API障害：候補をキューに退避し、復旧後に再判定する（カード反映遅延は許容）
- 権限外アクセス：403を返し監査ログに記録する
- エクスポート失敗：ユーザーへトーストで通知し再試行を案内する
