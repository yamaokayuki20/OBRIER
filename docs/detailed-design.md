#### 1.1.1 カードの表示バリエーション

感謝は一言のこともあれば長文のこともある。**カードの丈は全枚そろえたまま**、量の違いは本文の文字サイズと行数で受け止める。判定は本文の文字数（改行を除く）で行う。

| 種別 | 判定条件 | 見せ方 |
|---|---|---|
| 短い一言 | 本文14文字以下 | 17px・行間1.95・字間広め・中央揃え。**3行**まで。余白で受ける |
| 中くらい | 本文15〜53文字 | 既定の見せ方。14.5px・行間2.05・中央揃え。**4行**まで |
| 長文 | 本文54文字以上 | 左寄せ・13px・行間1.9・**5行**で止め（line-clamp）、下に「…続きは詳細で」を添える |

- カードの高さは種別によらず一定（268px）。行数で止めることで、一覧の縦の並びが崩れないようにする
- **拡大詳細（S05）では省略しない。** 全文をそのまま表示し、長い場合は詳細の中でスクロールして読む
- 分量による扱いの差は見せ方のみで、順位付け・優劣の表現は行わない
- 絵文字リアクション（F04）はカードを作らない。アルバムには出さず、カタチ画面（S02）での件数表示のみとする

### 1.4 S05 カード拡大詳細

カードを押すと開く詳細ビュー。カードの裏面（めくり）は持たず、押下で直接この画面を開く。

#### 1.4.1 構成（上から順）

| 順 | 要素 | 仕様 |
|---|---|---|
| ① | ヘッダー | 送り主アバター（濃紺）・送り主名・チャネル名・日時・閉じる（✕） |
| ② | オブリエのメモ | AI要約（経緯・回数などの文脈を1〜2文） |
| ③ | やり取りの流れ | 経緯の発言列を時系列表示。感謝発言はタグ色で塗った吹き出しで強調し、直下に「この言葉を保存しました」と添える。添付はファイルチップで表現 |
| ④ | 元のメッセージを開く | 「Slackで開く」／「Teamsで開く」ボタン。外部リンクアイコンを付す。**出典を表すタグ（バッジ）は置かない**（出典はこのボタンの文言で示す） |
| ⑤ | お気に入り | ★ボタン。押下ごとに登録／解除をトグルし、aria-pressedを更新する |
| ⑥ | じぶんのメモ | 本人のみ表示。上司・管理者が開いた場合はセクションごと描画しない |
| ⑦ | 誤検出報告 | 「これは感謝ではない」（F02） |
| ⑧ | 削除 | 「このカードを削除する」（本人のみ・確認ダイアログ必須・復元不可） |

- 文字色はアバターと同じ濃紺 #3A4A66 で統一する（見出し・本文・補助文とも濃紺の濃淡で構成する）
- 閉じる操作：✕ボタン（32px以上）・背景クリック・Escキー

#### 1.4.2 カード→拡大詳細の遷移

**表にカード・裏に詳細を貼った1つの要素を、要素ごと回して裏返す。** 要素は常に1つなので、入れ替わりの隙間も二重の重なりも原理的に起こらない。

| 項目 | 仕様 |
|---|---|
| 構造 | 3D空間を持つラッパー（`transform-style: preserve-3d`）に、表面＝カードの複製、裏面＝詳細シート（`rotateY(180deg)`）を重ねる。両面とも `backface-visibility: hidden` とし、回転の前半では表だけ、後半では裏だけが見える |
| 回転 | ラッパーの `rotateY` を 0°→180° に動かす。0.5を境に表と裏が自然に入れ替わるため、面を差し替える処理は行わない |
| 移動 | 開始位置（押されたカードの中心）から詳細の中心までの差分を、進行に合わせて0へ近づける |
| 拡大 | ラッパーの `scale` を「カード幅 ÷ 詳細幅」から 1 へ動かして表現する。表面はカードの実寸で置き、**逆数の scale**（1 ÷ 現在の scale）を当てて見かけの大きさを保つ。逆数はコマごとに焼き込むため、途中で伸び縮みしない |
| 所要・コマ | 380ms・等速（linear）・24コマのキーフレームを生成する |
| 元のカード | 遷移中は `visibility: hidden` にして隠し、閉じ終わったときに戻す |
| 閉じる | 同じキーフレームを逆順に生成して再生する（開くときと閉じるときで軌跡が一致する）。閉じ始めに詳細のスクロール位置を先頭へ戻す |
| 背景 | オーバーレイは開くとき200msでフェードイン、閉じるとき380msかけてフェードアウトする |
| モーション配慮 | `prefers-reduced-motion: reduce` では回転を行わず、表面を隠して詳細を即時表示・即時クローズする |

旧方式（カードの複製と詳細シートの2枚を90°で入れ替え、前半170ms／後半180ms／24msのハンドオフで重ねる）は、瞬間的に2枚に見えることがあったため廃止した。

#### 1.4.3 誤検出報告（F02）

| 項目 | 仕様 |
|---|---|
| 導線 | 拡大詳細の下部に「これは感謝ではない」を配置する。削除ボタンとは別扱いとし、視覚的にも分ける |
| 確認 | 「このカードを検出の誤りとして報告し、アルバムから外します。よろしいですか？」の確認ダイアログを表示する |
| 挙動 | POST /api/cards/{id}/feedback（type=not_thanks）を送信。成功時は詳細を閉じ、カードをアルバムから外す。トースト「報告しました。ありがとうございます」 |
| 集計 | 報告はdetection_feedbackに記録し、S09の検出品質モニタと週次の品質モニタリングに反映する |
| 学習 | 報告事例を判定プロンプトの負例に加え、同一送り主・同一表現の再発を抑えるユーザー別除外ルールを生成する |
| 削除との違い | 削除（F08）は本人の意思でアルバムから外すだけで学習には用いない。誤検出報告は検出器の学習に用いる。いずれも復元不可 |

### 1.6 S09 管理者設定

管理者のみアクセスできる独立画面。4つのセクションをタブで切り替える。本人ビュー・上司ビューと同じデザイン言語（方眼台紙・濃紺の文字色）を用いる。

| セクション | 要素 | 仕様 |
|---|---|---|
| (a) 連携設定 | Slack／Teams接続状態 | ワークスペース名・接続日時・トークン有効期限・最終取込時刻を表示。失効時は警告と「再連携」ボタンを出す |
| | 解析対象チャンネル | 取得済みチャンネルの一覧に対し、解析対象のオン／オフを切り替える。既定はパブリックチャンネルのみ。DMは対象外（変更不可） |
| | 再連携 | OAuth再認可へ遷移。完了までの取込停止期間を記録・表示する |
| | 過去ログ取込 | 初回取込バッチの進捗（対象月・処理済み件数）を表示する |
| (b) チーム・メンバー管理 | メンバー一覧 | 氏名・メールアドレス・所属チーム・直属上司・ロール（member/manager/admin）をテーブル表示。名前・チームで絞り込む |
| | 所属と上司の割当 | 行の編集でチームと直属上司を変更する。上司の変更は監査ログに記録し、変更以降の閲覧権限に反映する |
| (c) 監査ログ | 一覧 | 日時・操作者・操作（アルバム閲覧／レポート閲覧／エクスポート／設定変更）・対象ユーザーをテーブル表示。期間・操作者・操作種別で絞り込み、CSV出力に対応する |
| | 保持 | 1年間保持する。ログの編集・削除は行えない |
| (d) 検出品質モニタ | 誤検出報告 | 月次の誤検出報告件数の推移と、報告の多い送り主・表現の傾向を表示する |
| | 信頼度しきい値 | カード化の下限（既定0.80）を表示する。変更は運用パラメータとして扱い、変更時は監査ログに記録する |
| | 取りこぼし | 閾値未満で保存されなかった候補の件数のみ表示する（本文は保存していないため表示しない） |

**S09にもじぶんのメモは一切表示しない。** 管理者はメンバーのアルバムを閲覧できるが、じぶんのメモの本文・有無ともに取得できない。

### 1.7 節目演出（F09）

### 1.8 エクスポート（F13・F18）

| 形式 | 仕様 |
|---|---|
| CSV（アルバム） | S01の表示中の絞り込み条件に従う。列＝受信日時／送り主／チャネル／出典／本文／場面タグ／お気に入り。**じぶんのメモは含めない** |

## 2. API設計

| メソッド/パス | 概要 | 主な入出力 |
|---|---|---|
| GET /api/me/cards | 自分の感謝カード一覧 | in: tag, favorite, page ／ out: cards[], total |
| GET /api/cards/{id} | カード詳細（経緯・メモ含む） | out: card, story[], summary, source_url |
| POST /api/cards/{id}/feedback | 誤検出報告（本人のみ） | in: type=not_thanks ／ out: 204 |
| GET /api/me/shape | カタチ（タグ内訳・場面言語化・推移・リアクション数） | in: period(1w/1m/1y/3y/5y), compare?(6m/12m) ／ out: tags[], tops[]（最大10）, series{recv[], sent[]}, reactions{count}, compare?{tags[]} |
| GET /api/me/network | 広がりマップ | out: groups[{dept, senders[]}] |
| GET /api/me/sent | 送った感謝一覧 | out: cards[] |
| GET /api/me/milestones | 未表示の節目（F09） | out: milestones[{type, achieved_at}] |
| POST /api/me/milestones/{id}/seen | 節目の帯を閉じた記録 | out: 204 |
| GET /api/me/shape-reports | 月次カタチレポート（F19） | in: month? ／ out: months[] または report |
| POST /api/me/export | CSV／STAR書き出し | in: format(csv/star) ／ out: ファイルURL |

- 全APIは認証必須。上司系APIは対象ユーザーが自チーム所属かを検証し、閲覧を監査ログに記録する
- `/api/admin/*` は role=admin のみ許可し、操作を監査ログに記録する
- **じぶんのメモ（memo_text）とお気に入り（favorite）は、本人自身のリクエストに対してのみ返す。** 上司系・管理者系のレスポンス、レポート、エクスポート、監査ログには一切含めない（有無を示すフラグも返さない）

## 4. 検出ロジック詳細

### 4.1 判定パイプライン

| 段階 | 処理 | 備考 |
|---|---|---|
| ① 受信 | 連携層からメッセージ（本文・送信者・宛先・スレッド情報）を受け取る | bot発言・システム通知はここで破棄 |
| ② 候補抽出 | 感謝語彙辞書（ありがとう/助かる/さすが/おかげ/感謝 等）または感謝系絵文字リアクションに一致するものを候補化 | 辞書は運用で更新 |
| ③ LLM判定 | 候補発言＋同スレッド直前最大10件を入力し、JSONで出力：is_thanks／recipient／tag（既存タグへの割当または新規タグ名）／is_sarcasm／confidence（0〜1） | 皮肉・社交辞令はここで除外。タグは固定分類ではない |
| ④ カード化 | confidence≧0.80のみthanks_cardsに保存。0.80未満は保存せず統計のみ記録 | 閾値は運用パラメータ |
| ⑤ 経緯・要約 | 直前のやり取りからstoryを構成し、オブリエのメモを生成 | 生成失敗時はメモなしで保存する |

### 4.2 学習フィードバック

- 誤検出報告されたカードは非表示化し、報告事例を判定プロンプトの負例として追加する
- 同一送り主・同一表現での再発を抑えるユーザー別除外ルールを設ける
- 週次で誤検出率をモニタリングし、閾値・辞書を調整する

### 4.3 絵文字リアクションの扱い

感謝系絵文字（🙏 ✨ 👏 ❤ 等）のリアクションは、対象メッセージの投稿者宛ての「小さなありがとう」として件数のみ計上する（reaction_counts）。カードは生成せず、カタチ画面（S02）に「小さなありがとう ○件」として控えめに表示する。アルバム（S01）の累計カウンターと推移チャートの受信数には含めない（カード数と件数を混ぜない）。

## 5. バッチ処理設計

| ジョブ | 起動 | 処理概要 |
|---|---|---|
| 過去ログ取込 | 初回連携時 | 過去1年分を新しい月から順に取得し判定パイプラインへ投入。進捗を管理者設定（S09a）に表示 |
| 1on1準備メモ生成 | 毎月1日 6:00 | 前月分の集計・称賛候補の選定・アラート判定・問い候補の生成を全ユーザー分実行 |
| カタチレポート生成 | 毎月1日 6:30 | 本人向け月次カタチレポート（F19）を生成。前月からのタグ内訳の変化と代表エピソードを言語化する |
| 節目判定 | 日次 1:00 | 累計100通・初めての送り主・利用1周年の到達を判定しmilestonesに登録する（F09） |
| 年間アルバム生成 | 要求時（非同期） | 指定年のカードからPDFを生成し、完了後にダウンロードリンクを提示する（F18） |

| 検出品質集計 | 週次 | 誤検出報告率・閾値未満件数を集計し、S09dの検出品質モニタに反映する |

### 5.1 アラート判定ロジック

月次レポート生成時に以下を判定し、該当時のみアラート文を出力する。本人へは通知しない。
- 受信数が前月比50％以上減少し、かつ2か月連続で減少している
- 送信数が前月比50％以上減少し、かつ2か月連続で減少している
- 文面は断定を避け、「〜のサインかもしれません。1on1で聞いてみてください」の形式とする

## 6. 通知文言仕様

### 6.1 方針

- 順位・比較・催促を想起させる表現は用いない
- **キザな言い回しを避ける。** 操作の結果は平易に伝える（「綴じました」ではなく「保存しました」）。「綴じる」はサービス名の由来・コンセプト説明にのみ用い、UIの操作フィードバックには使わない

### 6.2 文言一覧

| 種別 | 文言テンプレート |
|---|---|
| 週次メール（1件以上） | 件名：今週の、あなた宛てのことば ／ 本文：今週は、あたたかい言葉が{n}通とどいています。{送り主}さんからの一言も、アルバムに残っています。 |
| 新着（アプリ内） | {送り主}さんから、あたたかい言葉がとどいています |
| 拡大詳細の感謝発言 | この言葉を保存しました |
| お気に入り登録／解除 | お気に入りに登録しました ／ お気に入りを外しました |
| じぶんのメモ保存 | じぶんのメモを保存しました |
| じぶんのメモの注記 | このメモはあなただけに表示されます |
| 削除の確認 | 削除すると、あとから元に戻すことはできません。このカードを削除しますか？ |
| 削除の完了 | カードを削除しました |
| 誤検出報告の確認 | このカードを検出の誤りとして報告し、アルバムから外します。よろしいですか？ |
| 誤検出報告の完了 | 報告しました。ありがとうございます |
| 節目（累計100通） | 受け取った言葉が100通になりました |
| 節目（初めての送り主） | {送り主}さんから、はじめての言葉がとどきました |
| 節目（利用1周年） | オブリエをはじめて1年になりました |
| アラート（上司向けアプリ内） | {name}さんの最新の準備メモに、気にかけたいサインがあります |

## 7. エラー・例外設計

- 連携失敗（トークン失効）：管理者に再認可を促すメールを送り、取込停止期間を記録する
- LLM API障害：候補をキューに退避し、復旧後に再判定する（カード反映遅延は許容）
- 権限外アクセス：403を返し監査ログに記録する
- エクスポート失敗：ユーザーへトーストで通知し再試行を案内する
